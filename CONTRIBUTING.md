# Правила разработки (Go)
- Все ошибки обрабатываются явно (никаких `_ = err`).
- Тесты: table-driven, покрытие ≥ 70% для критичных модулей.
- Коммиты: `[P1.2] Добавлен парсинг .docx`.
- PR не мержится без зелёного CI (golangci-lint + go test).
- Перед мержем сверить, за какой коммит идёт голосование: `git rev-parse HEAD` ветки совпадает
  с head PR, а `git status --porcelain` в рабочем дереве пуст. Мерж во время незавершённого раунда
  правок теряет последний коммит — он остаётся на закрытом PR и в main не попадает (#51 → #53).
- PR задачи `[P*]` обязан содержать правку README.md: раздел «Локальный запуск» с командой, флагами, примером вызова, ожидаемым результатом и кодами выхода.
- Клиентские документы из `docs/` в репозиторий не попадают: фикстуры тестов — base64-константы в `_test.go`.
