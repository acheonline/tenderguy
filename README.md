# tenderguy

## P1.1 — сканер директорий и определение типов файлов

Обход переданного каталога и классификация всех файлов (.docx/.xlsx/.pdf и прочие).
Путь задаётся только флагом `--input-dir`, пути в коде не фиксируются.

```bash
go build -o tenderguy ./cmd/tenderguy
./tenderguy --input-dir "docs/НЭО поставка RedCheck"
./tenderguy --input-dir "docs/ТЭК СПб сервис WAF/Заявка" --format json
```

Проверяемый вход эпика P1 (`poc.md`) — оба пакета целиком: `docs/НЭО поставка RedCheck/`
(документация + заявка) и `docs/ТЭК СПб сервис WAF/Заявка/`.

Тип определяется по содержимому (заголовок PDF, структура OOXML-архива), расширение
служит вторым признаком. Если расширение противоречит содержимому, файл классифицируется
по содержимому и попадает в раздел «Расхождение расширения и содержимого».
Lock-файлы редакторов (`.~lock.…#`, `~$…`), файлы ОС и служебные хвосты помечаются как
`service`, архивы и старый бинарный MS Office — как `archive`/`office_legacy` с указанием,
что для них нужен конвертер. Служебные каталоги (`.git`) из обхода исключаются, список
исключений печатается в отчёте.

Коды выхода: `0` — обход прошёл без замечаний, `1` — есть замечания (файл не читается,
символическая ссылка), `2` — ошибка в аргументах, `3` — неверный путь: каталога нет или
это не каталог (текст ошибки формулируется человеку, а не только логу CI).

Тесты: `go test ./...` (табличные, покрытие ≥ 50 % по `CONTRIBUTING.md`), линтер: `golangci-lint run ./...`.
